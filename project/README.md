# ChurnGuard: прогноз риска оттока клиентов

Итоговый мини-проект по курсу «Инженерия Искусственного Интеллекта».

## 1. Паспорт проекта

- **Название проекта:** ChurnGuard: сервис прогнозирования риска оттока клиентов
- **Автор:** Чобан Александр Александрович
- **Группа:** ЭФБО-14-24
- **Контакт:** parallax071@gmail.com

**Краткое описание:**  
Проект решает задачу бинарной классификации: по признакам клиента нужно оценить вероятность оттока. Используются синтетические обезличенные табличные данные, baseline-модель `LogisticRegression` и финальная модель `RandomForestClassifier`. Результат проекта - воспроизводимый пайплайн обучения и REST API на FastAPI с endpoint-ами `/health` и `/predict`.

## 3. Требования и установка

Требуется Python `>=3.10`. В проекте не используются внешние базы данных, облачные API или реальные секреты.

```bash
cd project
python -m venv .venv

# Windows
.venv\Scripts\activate

# Linux / macOS
source .venv/bin/activate

# Установить зависимости
pip install --upgrade pip
pip install -r requirements.txt
```

## 4. Как запустить проект

### 4.1. Сгенерировать данные и обучить модель

```bash
cd project
python -m src.train
```

Команда создает `data/churn_train.csv`, `data/churn_sample.csv`, обучает две модели, сохраняет финальную модель в `artifacts/churn_model.joblib`, а метрики - в `artifacts/metrics.json`.

### 4.2. Запустить API-сервис

```bash
cd project
python -m src.service
```

Сервис поднимается на `http://127.0.0.1:8000`.

Ключевые endpoint-ы:

- `GET /health` - проверка доступности сервиса и модели.
- `POST /predict` - прогноз вероятности оттока по признакам клиента.

Пример проверки:

```bash
curl http://127.0.0.1:8000/health
```

Пример запроса к модели:

```bash
curl -X POST http://127.0.0.1:8000/predict ^
  -H "Content-Type: application/json" ^
  -d "{\"age\":34,\"tenure_months\":8,\"monthly_spend\":92.5,\"support_tickets\":3,\"late_payments\":1,\"contract_type\":\"month-to-month\",\"has_autopay\":0,\"uses_mobile_app\":1,\"satisfaction_score\":5.2}"
```

Swagger UI доступен в браузере по адресу `http://127.0.0.1:8000/docs`.

## 5. Данные

Данные синтетические и не содержат персональной информации. Генерация реализована в `src/data.py`: признаки имитируют типичный профиль клиента подписочного сервиса.

Признаки:

- `age` - возраст клиента;
- `tenure_months` - сколько месяцев клиент пользуется сервисом;
- `monthly_spend` - средний ежемесячный платеж;
- `support_tickets` - количество обращений в поддержку;
- `late_payments` - количество просрочек платежа;
- `contract_type` - тип договора: `month-to-month`, `one-year`, `two-year`;
- `has_autopay` - подключен ли автоплатеж;
- `uses_mobile_app` - пользуется ли клиент мобильным приложением;
- `satisfaction_score` - оценка удовлетворенности от 1 до 10;
- `churn` - целевая переменная: `1` означает отток, `0` означает удержание.

## 8. Ограничения и дальнейшая работа

Текущая версия использует синтетические данные, поэтому метрики показывают работоспособность подхода, но не качество на реальном бизнес-домене. В сервисе нет авторизации, долговременного хранения запросов и мониторинга распределения входных признаков.

Дальше проект можно развивать так:

- заменить синтетические данные открытым или корпоративным обезличенным датасетом;
- добавить подбор гиперпараметров через `GridSearchCV` или `RandomizedSearchCV`;
- добавить мониторинг drift-а признаков;
- сохранять историю предсказаний;
- добавить Dockerfile и CI-проверки.
